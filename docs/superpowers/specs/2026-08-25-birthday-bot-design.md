# Birthday Reminder Bot — Design Spec

Дата: 2026-08-25
Статус: draft → на проверке у пользователя

## Контекст и цель

Текущий бот в репозитории — финансовый трекер (aiogram + Airtable). Требуется полностью
переделать его в бот-напоминалку о днях рождения. Старый функционал (финансы, Airtable)
убирается.

**Назначение:** пользователь вносит людей и их даты рождения, бот присылает напоминание
в день рождения. Мультитенантный — каждый пользователь со своим списком и настройками.

## Требования (зафиксированы с пользователем)

1. **Аудитория**: несколько пользователей, у каждого свой список людей и свои настройки
   (часовой пояс, время уведомления).
2. **Хранилище**: SQLite.
3. **Напоминания**: только в день рождения (без предварительных предупреждений за день/неделю).
4. **Год рождения**: по желанию. Если указан — показываем возраст и юбилеи; если нет —
   просто напоминаем о дате.
5. **Функции**:
   - Естественный ввод текста (`Мама 15.03.1990`).
   - Wishlist / идеи подарков к человеку.
   - Просмотр: сегодня / ближайшие / все.
6. **CSV-импорт**: не нужен.

## Архитектура

**Подход A — единый процесс: aiogram + APScheduler.** Бот (long-polling) и планировщик
живут в одном процессе, в одном event loop. APScheduler запускает один джоб (раз в час),
который делает рассылку.

Альтернативы (отвергнуты):
- B (два процесса: бот + воркер-планировщик) — сложнее деплой, два dyno.
- C (чистый asyncio-loop без APScheduler) — изобретаем APScheduler, нет устойчивости.

### Структура файлов

```
my_bot/
├── bot.py            # aiogram: хендлеры, FSM, команды
├── scheduler.py      # APScheduler: джоб ежедневной рассылки
├── db.py             # слой работы с SQLite (aiosqlite), инициализация схемы
├── parser.py         # парсинг естественного ввода даты рождения
├── config.py         # BOT_TOKEN, путь к БД, дефолты
├── requirements.txt
└── Procfile
```

### Ответственность компонентов

- **`db.py`** — единственный модуль, работающий с SQLite (через `aiosqlite`). Создаёт схему
  при старте, предоставляет CRUD: `add_user`, `add_person`, `get_people_with_birthday_on(...)`,
  `mark_sent(...)`, `already_sent(...)`, и т.д. Остальные модули обращаются к БД только
  через эти функции.
- **`parser.py`** — чистая функция `parse_birthday(text) -> (name, day, month, year_or_None) | None`.
  Не трогает БД, не шлёт сообщения. Тестируется изолированно.
- **`bot.py`** — хендлеры и FSM. Делегирует в `db.py` и `parser.py`, не знает про SQL.
- **`scheduler.py`** — настраивает `AsyncIOScheduler`, регистрирует джоб, вызывает логику
  рассылки (`check_and_send(bot)`).
- **`config.py`** — `BOT_TOKEN`, путь к `bot.db`, `DEFAULT_NOTIFY_HOUR=9`,
  `DEFAULT_NOTIFY_MINUTE=0`, `DEFAULT_TZ="Europe/Moscow"`.

### Жизненный цикл

При старте `bot.py` инициализирует БД (создаёт таблицы), запускает `AsyncIOScheduler`,
затем стартует long-polling. Оба работают в одном event loop.

## Модель данных (SQLite)

```sql
CREATE TABLE users (
    chat_id        INTEGER PRIMARY KEY,
    tz             TEXT NOT NULL DEFAULT 'Europe/Moscow',
    notify_hour    INTEGER NOT NULL DEFAULT 9,
    notify_minute  INTEGER NOT NULL DEFAULT 0,
    created_at     TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE people (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    user_chat_id  INTEGER NOT NULL REFERENCES users(chat_id) ON DELETE CASCADE,
    name          TEXT NOT NULL,
    birth_day     INTEGER NOT NULL,   -- 1..31
    birth_month   INTEGER NOT NULL,   -- 1..12
    birth_year    INTEGER,            -- NULL = год не указан
    created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_people_user_date ON people(user_chat_id, birth_month, birth_day);

CREATE TABLE wishes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    person_id   INTEGER NOT NULL REFERENCES people(id) ON DELETE CASCADE,
    text        TEXT NOT NULL,
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE sent_reminders (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    person_id   INTEGER NOT NULL REFERENCES people(id) ON DELETE CASCADE,
    event_date  TEXT NOT NULL,            -- 'YYYY-MM-DD', дата ДР в этом году
    sent_at     TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(person_id, event_date)
);
```

### Ключевые решения модели

- Дата хранится тремя полями (`birth_day`, `birth_month`, `birth_year`), а не одной строкой:
  удобно искать ДР сегодня индексом по `(month, day)`, `birth_year` может быть `NULL`.
- Часовой пояс — IANA-строка (`Europe/Moscow`), не смещение. Через `zoneinfo` корректно
  учитывается летнее/зимнее время.
- `sent_reminders` с `UNIQUE(person_id, event_date)` — механизм «ровно одно напоминание
  на один день рождения»: защита от дублей при гонках и перезапусках.
- `ON DELETE CASCADE` — удаление человека чистит его wishlist и журнал отправок.
- Пользователь создаётся лениво при первом взаимодействии с дефолтами, меняет через
  `/settings`.

## Логика рассылки (scheduler)

Один джоб, запускается **раз в час** (в :05 каждого часа). Не «раз в день», потому что
пользователи в разных поясах и у каждого своё время уведомления.

### Алгоритм `check_and_send(bot)`

```
для каждого пользователя u в users:
    now_local = datetime.now(ZoneInfo(u.tz))
    сегодня_у_юзера = now_local.date()

    если now_local < today_at(u.notify_hour, u.notify_minute, u.tz):
        пропустить                                  # рано

    люди = get_people_with_birthday_on(u.chat_id, сегодня.day, сегодня.month)
    для person в люди:
        event_date = дата_ДР_в_этом_году(person, сегодня_у_юзера)
        если already_sent(person.id, event_date):
            пропустить
        текст = сформировать_сообщение(person, event_date)
        bot.send_message(u.chat_id, текст)
        mark_sent(person.id, event_date)
```

### Формирование сообщения

- Без года: `🎂 Сегодня день рождения: Мама`
- С годом: `🎂 Сегодня у Мамы день рождения — исполняется 35!`
- Юбилей (кратный 10): `🎂 Сегодня у Мамы юбилей — исполняется 50! 🎉`
- С wishlist добавляется блок:
  ```
  💡 Идеи подарков:
   • цветы
   • билет в театр
  ```

### Свойства

- **Часовые пояса корректны** — сравнение и «сегодняшняя дата» в локальном времени
  пользователя через `zoneinfo`.
- **Защита от дублей** — `sent_reminders` с UNIQUE, даже при двойном запуске джоба.
- **Устойчивость к сбоям** — если процесс лежал, при следующем запуске джоб видит
  «местное время > 09:00, за сегодня не отправлено» и отправляет с опозданием.
- **29 февраля** — в невисокосный год ДР 29.02 считается наступившим 28.02.

### Почему раз в час

Для бота на несколько человек проверка каждую минуту избыточна. Раз в час — задержка
уведомления ~1 час относительно заданного времени, что для ДР приемлемо. При желании
меняется на `*/15 min`.

## Команды и FSM

### Команды

| Команда | Действие |
|---|---|
| `/start` | Приветствие, список команд. Лениво создаёт пользователя. |
| `/add` | Добавить человека (естественный ввод). |
| `/list` | Все люди, отсортированы по ближайшему ДР. |
| `/today` | Чьи ДР сегодня. |
| `/upcoming` | Ближайшие ДР (на 30 дней вперёд). |
| `/person` | Карточка человека: дата, возраст, wishlist, кнопки. |
| `/settings` | Часовой пояс и время уведомления. |
| `/help` | Краткая справка. |
| `/cancel` | Отменить текущую FSM-операцию. |

### Естественный ввод

В состоянии по умолчанию (без команды) — `Мама 15.03.1990` → бот парсит, подтверждает,
сохраняет. `/add` переводит в то же состояние и просит ввести `Имя дата`.

### FSM-состояния

```
AddPerson:    waiting_input      # «Мама 15.03.1990»
EditPerson:   waiting_field      # выбрали поле, ждём новое значение
DeletePerson: waiting_confirm    # кнопка подтверждения
AddWish:      waiting_text       # текст идеи подарка
Settings:     waiting_tz         # выбор часового пояса
Settings:     waiting_time       # «09:00»
```

### Навигация

Inline-кнопки (как в прежнем финансовом боте):
- `/list` → список с кнопками на каждого → карточка `/person`.
- Карточка: `Изменить`, `Удалить`, `＋ Идея подарка`, `Показать идеи`.
- `/settings`: 4–5 популярных поясов кнопками (Москва, Екатеринбург, Красноярск,
  Владивосток) + «ввести свой» → просим `Europe/Moscow` текстом, валидируем через `zoneinfo`.

## Парсер (`parser.py`)

```python
def parse_birthday(text: str) -> tuple[str, int, int, int | None] | None:
    """
    'Мама 15.03.1990' -> ('Мама', 15, 3, 1990)
    'Мама 15.03'      -> ('Мама', 15, 3, None)
    'Мама 15 марта'   -> ('Мама', 15, 3, None)
    """
```

### Форматы даты (хвост строки)

- `15.03.1990`, `15.03` (точка-разделитель)
- `15/03/1990` (слэш)
- `15 марта`, `15 марта 1990` (месяц словом)

### Разделение имя/дата

Дата — хвост строки, удовлетворяющий шаблону. Всё левее — имя (может быть из нескольких
слов: `Мама и папа 15.03`).

### Словарь месяцев

`янв, фев, мар, апр, май, июн, июл, авг, сен, окт, ноя, дек` → 1..12. Любой падеж
(`янв*`, `мар*`).

### Валидация

- День `1..31`, месяц `1..12`.
- Если год указан — реальная проверка через `datetime(year, month, day)` (отбракует `31.02`).
- Год: только 4 цифры (двузначные не поддерживаем, явно). Год `< 1900` или в будущем → ошибка.

### Что НЕ делаем

- Без полноценного NLP/AI-парсинга (лишняя зависимость и стоимость, регулярки покрывают
  реальные случаи).
- Без относительных дат («через неделю»).

### Сообщение при ошибке

> Не понял. Пример: `Мама 15.03.1990` или `Мама 15 марта` (год — по желанию).

## Обработка ошибок

- **БД недоступна**: хендлеры ловят исключение, отвечают «Что-то сломалось, попробуй позже»,
  логируют. Бот не падает.
- **`bot.send_message` упал с `TelegramForbiddenError`** (пользователь заблокировал бота /
  удалил чат): помечаем `sent_reminders` как отправленный (чтобы не пытаться снова каждый
  час), логируем WARNING. Другие ошибки отправки → не отмечаем, пробуем на следующем
  запуске.
- **Невалидный ввод в FSM**: бот просит повторить, состояние не сбрасывается.
- **Двойной запуск джоба**: защита на уровне `UNIQUE(person_id, event_date)` — второй
  `INSERT` упадёт.
- **Логирование**: INFO по умолчанию, ошибки рассылки — WARNING, ход проверки ДР — DEBUG.

## Тестирование

- **`parser.py`** (юнит, `pytest`, без моков): все форматы дат, имя из нескольких слов,
  отсутствие года, невалидные даты (`31.02`, `15.13`), пустой ввод, год в будущем,
  двузначный год (отвергается).
- **`db.py`** (интеграционные, in-memory SQLite `:memory:`): добавление пользователя/человека,
  каскадное удаление, проверка дубля `sent_reminders`, поиск ДР сегодня.
- **`check_and_send`** (с моком бота): пользователь с поясом, где «сейчас 09:30», человек с
  ДР сегодня → `send_message` вызван, `sent_reminders` появился. Второй вызов →
  `send_message` не вызван.
- **29 февраля**: человек `29.02`, невисокосный год → ДР считается `28.02`, отправка в
  этот день.
- Хендлеры/FSM сознательно не тестируются — покрываем логику, а не aiogram-обвязку.

## За рамками (явно)

- Предварительные напоминания (за день/неделю) — не делаем.
- CSV/.ics импорт-экспорт — не делаем.
- Групповые чаты — не делаем (мультитенант в личке).
- AI/голосовой ввод — не делаем.
- Двузначные годы — не поддерживаем.
